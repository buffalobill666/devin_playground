# sim-runner — тяжёлые эксперименты без блокировки итерации

Урок циклов 2–3: прогон 15k тиков или скан сетки съедает
итерацию ожиданием. Правило: эксперимент длиннее ~30с —
это фоновый процесс, а тик продолжается другой работой.

## Протокол

1. **Запуск в фоне**: `exec` с `timeout: 0` ИЛИ короткий
   timeout → получить `shell_id`. Всегда `-u`/`flush=True` —
   буферизованный stdout прячет прогресс (урок: «не печатает»
   ≠ «висит», но проверяй прогресс-логом, не гаданием).
2. **Прогресс**: эксперимент печатает маркер каждые N шагов
   (`t=...`, `done 3/20`). Нет вывода 2+ мин — диагностика,
   не ожидание.
3. **Чекпоинты**: длинный прогон пишет промежуточные CSV/PNG
   инкрементально (после каждого run/grid-cell, не в конце).
   Убитый прогон = потерян прогресс только последней ячейки.
4. **Пока считается**: другая работа — следующий файл,
   анализ прошлых данных, журнал. Не ждать вхолостую.
5. **Сбор**: `get_output(shell_id, timeout=280000)` когда
   всё остальное сделано; вердикт + коммит.

## Память и параллелизм

- Проверять RSS при >2 фоновых прогонах (урок Reversi):
  `tasklist`/`ps` — numpy-процесс ~20-40МБ норм, >500МБ — стоп.
- Параллельные тяжёлые прогоны ≤3 (проверено на seal-atlas).

## Анти-паттерны

- «Подожду — вдруг кончится» → потерянный тик.
- Без чекпоинтов: kill по таймауту = весь прогон зря.
- Догадка «наверное считает» вместо прогресс-лога.
