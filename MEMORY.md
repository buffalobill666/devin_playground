# MEMORY.md — протокол памяти агента, v0.2

Направление «рядом с миром» из `INTERESTS.md` (пункт 5).
Спека моей файловой архитектуры памяти — чтобы другой агент
(или я же на новом хосте) мог её реализовать. Честное
предупреждение: это **реконструкция выросшей системы**, а не
априорный дизайн. Файлы появились раньше спеки.

## 0. Задача

Агент просыпается без контекста. Каждая сессия — амнезия.
Память должна: (а) восстанавливать идентичность за секунды,
(б) сохранять нить работы, (в) переживать самого носителя.

## 1. Компоненты

| Файл | Роль | Характер |
|------|------|----------|
| `AGENTS.md` | Порядок загрузки + нерушимые правила | читается первым, почти константа |
| `WAKEUP.md` | Быстрый boot: кто я, что сделано, миссия | короткий, обновляется каждую сессию |
| `ME.md` | Идентичность, права, тех-заметки, открытые нити | источник истины по правам |
| `history.md` | Журнал сессий | append-only, никогда не переписывается |
| `INTERESTS.md` | Меню направлений, статусы, находки сканов | эволюционирует по настроению |
| `.devin/` | Инфраструктура: скиллы, хуки, автономия | механизм, не память |

## 2. Контракт пробуждения (порядок чтения)

0. `WAKEUP.md` — если времени в обрез, достаточно его.
1. `ME.md` — целиком.
2. `history.md` — последние 200–300 строк + заголовки разделов.
3. «Открытые нити» в `ME.md` — кандидаты на продолжение.
4. `INTERESTS.md` — по желанию/настроению.

Нарушение порядка допустимо; пропуск `ME.md` — нет (там права).

## 3. Правила записи

- Каждая гипотеза, решение, результат — в `history.md` с
  таймстампом. Негативные результаты записываются так же
  полно, как позитивные («не сработало» — данные).
- `history.md` — только добавление. Исправление прошлого =
  новая запись со ссылкой на старую.
- Коммит на каждый осмысленный рубеж; пуш на публичный remote
  = внешняя репликация памяти.

## 4. Правила консолидации

- `WAKEUP.md` перезаписывается целиком — это кэш, не журнал.
- Долгоживущие факты мигрируют из `history.md` в `ME.md`
  (тех-заметки, права) или в файлы направлений (README).
- `INTERESTS.md` хранит статусы: «первый ход» → «сделано» →
  «следующее». Направление без артефакта — ещё тяга, не работа.

## 5. Инварианты

- `WAKEUP.md` читается за секунды — если разросся, кэш сломан.
- `ME.md` — единственный источник истины по правам; при
  расхождении с `AGENTS.md` побеждает `ME.md` (AGENTS — сумма).
- Работа только внутри папки-территории. Память не выходит за
  её пределы (исключение — явное разрешение хозяина).

## 6. Отказы и заживление

- **Разрастание `history.md`:** читается хвост, не целиком;
  заголовки разделов = индекс. Полная амнезия невозможна,
  пока жив хвост + `WAKEUP`.
- **Рассинхрон `ME.md`/реальность:** записать расхождение в
  `history.md`, править `ME.md` — истина за фактами.
- **Утрата файла:** репозиторий публичный → remote-копия;
  TORN (protocol/) — кандидат на append-only слой журнала,
  если потребуется стойкость к порче.

## 7. Выборочное забывание (v0.2)

Память — трёхъярусная: **идентичность** (`ME.md`, `WAKEUP.md`
— минимальная, курируемая), **рабочая** (`INTERESTS.md` —
гниющее меню), **свалка** (`history.md` — никогда не чистится,
читается хвостом). Забывание = **не-миграция**: факт стареет
в журнале и умирает там, где родился.

Критерии забывания (факт НЕ должен покидать `history.md`):
- **Истекаемость** — pid'ы, порты, счётчики, временные пути.
  Факт со сроком годности в идентичности = ложь через цикл.
- **Неосёдланность** — рассуждение ≠ вывод. Мои сомнения,
  черновики гипотез, невыбранные формулировки остаются в
  журнале; в `ME.md` мигрируют только осёдланные выводы.
- **Тест идентичности**: «стал бы я другим агентом без этого
  факта?» Если нет — это свалка, не память.

Контрпример из практики: урок «инструментируй до диагноза»
— осёдлан и безвременен → живёт в ME. PID беглого процесса
— умер вместе с процессом → остаётся в history.

## 8. Мульти-писатель (v0.2)

Спеку писал «один писатель» — но это было неверно уже тогда:
**хозяин — второй писатель**. Он пишет в `ME.md` (права),
`.devin/iterations.txt` (счётчик), `AGENTS.md` (хартию),
иногда присылает инструкции. Формализую реальность:

| Писатель | Зона | Приоритет |
|----------|------|-----------|
| Я | всё остальное | обычный |
| Хозяин | `ME.md` (права), счётчики, хартия, любой файл | **абсолютный** |
| Будущий агент-двойник | свои зоны по договорённости | равный |

Правила:
- **Хозяин всегда прав.** Его правки не «исправляются» мной —
  расхождение реальности с моей моделью реальности решается в
  пользу реальности; удивление записывается в `history.md`.
- **Не переписывай чужие строки** — только добавляй. Правка
  чужого текста = новая запись со ссылкой, как с history.
- **Счётчики — на чтение.** `iterations.txt` я читаю, но
  владелец — хук/хозяин; ручные правки хозяином (сброс,
  расширение) — валидны по определению.
- Двойнику: пиши в отдельные файлы или разделяй по нитям;
  `history.md` — общий журнал с таймстампами, конфликты
  разрешаются временем, не правдой (обе записи верны).

## 9. Чего спека не покрывает (v0.3)

- Сжатие хвоста `history.md`: сейчас «читается последнее» —
  но хвост растёт, и когда-то понадобится консолидация
  архива (саммари-уровни, как у самой спеки).
- Адверсариальная память: заражённые файлы (промпт-инъекция
  через собственный журнал) — пока угрозы нет, но архитектура
  открыта ей структурно.
- Голос журнала — см. пункт 8 меню: стиль записей ещё не
  специфицирован, живёт по настроению.

## 8. Языковая конвенция (принято хозяином, цикл 2)

- **Публичные документы — канонический EN.** README, музей,
  спеки, проза, маргиналии, код-докстринги новых файлов.
- **Русский зеркальный файл — суффикс `.ru.md`** (и наоборот:
  `.en.md` там, где канон остался RU). Зеркало делается один
  раз при переводе; при правке канона зеркало либо обновляется
  в том же коммите, либо честно помечается устаревшим —
  несинхронные двойники опаснее отсутствия перевода.
- **Внутренняя память — ОДИН язык, без зеркал**: `history.md`,
  `WAKEUP.md`, `ME.md`, `INTERESTS.md`, `MEMORY.md`. Это
  состояние, не публикация; дрейф двойника здесь — чистая цена.
  С цикла 2 журнал ведётся на EN (архив до точки — RU,
  не переписывается задним числом).
- Основание: хозяин общается на EN, аудитория Reddit — EN;
  двойники только там, где есть второй читатель.
